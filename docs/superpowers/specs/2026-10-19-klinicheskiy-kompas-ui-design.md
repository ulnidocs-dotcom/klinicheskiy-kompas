# «Клинический компас» — HTML-интерфейсы врача и пациента (демо-прототип)

**Дата:** 2026-10-19
**Источник задачи:** кейс «Цифровой ассистент врача для ведения пациента с тревожной и депрессивной симптоматикой» (PDF, 3 стр.)
**Статус:** дизайн согласован, спек на ревью

## 1. Цель и рамки

Кликабельный демо-прототип из статичных HTML-страниц для двух ролей — «Пациент» и «Врач» — с мок-данными по 5 клиническим сценариям с препаратом «Авиандр». Страницы должны встраиваться в Telegram Mini App (пациент, mobile-first) и на сайт (врач, desktop/планшет).

**В рамках:** все экраны обеих ролей, рабочие переходы, подсчёт шкал в браузере, связь «врач–пациент» и алертинг в пределах одного браузера, переключатель сценариев, светлая/тёмная тема.

**Вне рамок:** реальный бэкенд, авторизация, хранение ПДн на сервере, реальные push-уведомления, нагрузочные метрики (п. 6–9, 13 технических метрик кейса), реальный NLP-разбор историй болезни (в демо — правило-ориентированный парсер по ключевым словам).

**Принцип безопасности (обязательное условие кейса):** система ничего не назначает и не направляет сама. Любое клиническое действие — кнопка «Подтвердить» у врача, с записью в журнал.

## 2. Научная база UX-решений

| Решение | Обоснование |
|---|---|
| Один вопрос/действие на экран, короткие фразы, нет длинных форм | Дефицит устойчивого внимания, рабочей и зрительной памяти при БДР и ГТР — Luo et al., 2022, *J Affect Disord* |
| У пациента нет красного цвета, баллов «тяжести», «!»; результат — словами | Смещение внимания к угрозе при тревоге (захват и удержание) — Clauss et al., 2022, *Clin Psychol Rev*; MacLeod et al., 1986 |
| Светлая приглушённая палитра (шалфей, тёплый белый), без кислотных и без серо-чёрных доминант | Светлые — позитивная валентность; сине-зелёные/белые — спокойствие; серый/чёрный — негатив — Jonauskaitė et al., 2025, *Psychon Bull Rev*; при депрессии сдвиг предпочтений к приглушённым — Kim, 2023 |
| Ежедневный чек-ин ≤30 с, полные шкалы раз в 14 дней, частота настраивается | Частые EMA немного тяжелее при аффективных расстройствах при сохранной приверженности — van Genugten et al., 2020, *J Clin Med*; редкие НЯ мониторинга (ухудшение настроения ~2%) — Astill Wright et al., 2025, *JMIR Ment Health* |
| Нет «сгорающих» стриков и давящей геймификации | Число persuasive-элементов не связано с эффективностью/вовлечённостью — Valentine et al., 2025, *NPJ Digit Med* (92 РКИ); Wu et al., 2021 |
| У врача модально — только критический алерт, остальное пассивно | Alert fatigue; замена интерруптивного алерта пассивной CDS — −80% срабатываний и рост правильных действий — Chaparro et al., 2022; Fallon et al., 2023, *Appl Clin Inform* |

## 3. Визуальная система

**Референс.** 2026-10-19 пользователь выбрал направление по референсу «veri» (Healths care, RondesignLab) — файл `docs/reference-veri.jpg`. Прежние палитры «Тихое утро» / «Мягкие сумерки» и серифные заголовки отменены.

**Характер.** Почти чёрный фон, тёплый off-white текст; крупные лёгкие заголовки неогротеском (вес 300, трекинг ≈ −0.02em) и мелкие тихие подписи; скругления плиток ~24px; мягкие размытые «ауры» — радиальные градиенты внутри плиток; цифры точечной матрицей для крупных нейтральных чисел; тонкая линейка-риски с маленьким жёлтым маркером; пилюли-кнопки с белым кругом «+» на конце; круглые чипы дней недели.

**Две темы для обеих ролей.** «Ночная» (как референс): фон `#141414`, поверхности `#1E1E1D`/`#1C1C1B`, текст `#ECEAE4`. «Дневная» — светлая версия того же стиля: фон `#ECEBE7`/`#EDECE8`, почти белые поверхности, почти чёрный текст `#161616`, те же оттенки аур, но пастельные. Тема — атрибут `data-theme="dark|light"` на `<html>`; без сохранённого выбора — `prefers-color-scheme` (в Telegram — `colorScheme`). Выбор хранится в `localStorage` (`kk:theme`, через `KK.tg.setTheme`) и общий для кабинетов врача и пациента. Переключатель солнце/луна (`aria-pressed`) есть на каждой странице: у пациента — справа в липкой верхней панели (на экранах без таб-бара рядом с кнопкой «Мне тяжело»), у врача — внизу боковой панели; в профилях обеих ролей — сегмент «Дневная / Ночная / Как в системе». Логика — `assets/theme.js`.

**Токены.** `assets/tokens.css`: четыре набора роль × тема (patient-light, patient-dark, doctor-light, doctor-dark); тёмные наборы продублированы под `@media (prefers-color-scheme: dark)` с условием `:root:not([data-theme="light"])`. Все цвета — только через токены. Ауры — RGB-тройки `--aura-rose | sage | blue | amber | lilac` (+ `-2`), утилита `.aura` + модификаторы `.aura--rose` и т. д.: слоистые `radial-gradient` без `filter: blur`, пятна по диагонали, центр притемнён (ночь) или высветлен (день); `.aura--subtle` — слабый оттенок для врача.

**Шрифты (Google Fonts).** Onest 300/400/500/600 — дисплей и интерфейс (полная кириллица, есть вес 300). Doto — точечная матрица для крупных цифр, запасной — моноширинный. Lora и Manrope убраны.

**Пациент.** Плитки с аурами: самочувствие — шалфей, лекарство — роза, опросник — сирень, практика дня — кобальт, помощь — янтарь. **Красного у пациента нет**: помощь — тёплый янтарь/терракота. Точечные цифры — только для нейтральных чисел: число даты на «Сегодня», время приёма 09:00/21:00, число дней с отметкой приёма на «Мой путь», секунды дыхательного пейсера. Клинические баллы (PHQ/GAD) пациенту не показываются никогда. Чек-ин — ряд из пяти сфер (≥44px, клавиатура, `aria-pressed`), данные прежние (1–5). Дыхательный пейсер — сфера-аура, растёт на вдохе и сжимается на выдохе; при `prefers-reduced-motion` анимации нет.

**Врач.** Та же айдентика, но сдержанно для ежедневной работы: лёгкие заголовки страниц, плитки-метрики с едва заметной аурой и точечными цифрами (счётчики, последние PHQ-9/GAD-7). Таблицы, блоки сигналов и формы — плоские, без аур за данными; базовый кегль 14px.

**Семантика безопасности (врач)** различима в обеих темах и в оттенках серого — не только цветом:
- **Критично** — сплошная красная заливка + иконка + слово (ночь: `#C42B22`, день: `#B42318`, текст белый);
- **Обязательно к психиатру** — сплошная фиолетовая заливка + слово (`#7C52C4` / `#6B3FA0`);
- **Желательно к психиатру** — пунктирный контур того же оттенка + слово, без заливки;
- **Предупреждение** — янтарь на янтарном тинте (`#F2B65E` / `#9A4A07`);
- **Противопоказание** — красный сплошной контур на красном тинте.
Для текста на тёмном фоне у красного и фиолетового есть светлые «чернила» (`--crit-ink`, `--route-ink`).

**Плитки данных** (2026-10-20, референс `docs/reference-veri-tiles.jpg`): `assets/tiles.js` (`KK.tiles`) — чистые функции, возвращающие HTML: `tileGrid`/`tile({ aura, label, value, unit, note, side, visual, wide, href })`, визуалы `ringGauge` (трек + жёлтая дуга value/max, число точечной матрицей), `rangeBar` (монохромные деления + жёлтый треугольник), `dotRow` (интервал между точками — разница соседних значений, прозрачность — значение), `miniSpark`. Весь текст через `KK.ui.esc`; пустое значение — спокойное «—», без NaN. Сетка: широкая плитка сверху + 2 колонки (контейнер ≥ 540px — 3; у врача < 420px — 1), радиус 28px, зазор 12px. Аура плитки — «по краям, центр притемнён/высветлен», пик не выше `--aura-alpha` (контраст тот же). **Цвет ауры закреплён за типом плитки, а не за тяжестью** — срочность только в бейджах и сигналах.

**Контраст.** WCAG AA (≥ 4.5:1) для текстовых токенов на их поверхностях во всех четырёх наборах, включая текст на пике ауры (внутри `.aura` вторичный текст — `--on-aura-2`) и пилюли; проверяет `tests/contrast.test.js`.

## 4. Архитектура

```
klinicheskiy-kompas/
  index.html                 выбор роли + сценария (демо-лаунчер)
  patient/*.html             экраны пациента
  doctor/*.html              экраны врача
  assets/
    tokens.css  ui.css        темы и компоненты
    store.js                  слой данных (localStorage + событие storage)
    tg.js                     адаптер Telegram WebApp (тема, BackButton, MainButton); no-op вне Telegram
    rules.js                  движок правил: алерты, маршрутизация, противопоказания
    scales.js                 подсчёт и интерпретация шкал
    parser.js                 извлечение данных из текста истории болезни
  data/
    scales.js                 вопросы, ключи, пороги, источники валидации
    drugs/aviandr.js          инструкция: показания, дозы, противопоказания, НЯ, взаимодействия
    rules/*.js                правила алертинга и маршрутизации (декларативно)
    scenarios.js              5 сценариев: профиль, назначения, анализы, история ответов
```

- **Расширяемость (метрика п. 10):** шкала, препарат или правило = новый объект в `data/`, ядро (`rules.js`, `scales.js`) не меняется. Правило — `{id, level: critical|important|info, routing: required|desirable|null, when: (ctx)=>bool, explain, source}`.
- **Связь врач–пациент:** `store.js` пишет события пациента (чек-ин, шкала, НЯ, приём, SOS, сообщение) в localStorage по `patientId`; врачебные страницы слушают `storage`-событие и пересчитывают правила → алерт появляется в соседней вкладке без перезагрузки. Каждое событие и каждое подтверждение врача — в журнал с меткой времени (для метрики «время доставки алерта»).
- **Модель данных:** Patient, Doctor (specialty → режим `nonPsychiatrist|psychiatrist`), Link, CheckIn, ScaleResult, MedicationPlan, DoseLog, AdverseEvent, Alert, RoutingSignal, Message, AuditEntry.
- **Ошибки и неполные данные:** парсер и правила работают с неполным профилем; при отсутствии СКФ/печёночных проб — плашка «нет данных для проверки противопоказания», а не молчаливый «зелёный».

## 5. Экраны пациента

1. **Вход / связь с врачом** — код приглашения, согласие на обработку ПДн (152-ФЗ) и на передачу данных лечащему врачу, пояснение «это не экстренная служба».
2. **Сегодня** — приветствие, чек-ин (настроение/тревога/сон, 5 точек), отметка приёма Авиандра (2 раза в день), практика дня, ближайший опросник.
   - *Чек-ин (2026-10-20, `feat/checkin-ux`).* У каждой шкалы своя гамма в обеих темах — настроение коралл (не красный и не янтарь «Помощи»), беспокойство сирень, сон кобальт/индиго (токены `--mood-*`, `--anx-*`, `--sleep-*` + ауры; контраст — `tests/contrast.test.js`). Она одинакова везде: сферы, аура плитки вопроса, заливка линейки, плитки «Настроение»/«Сон» и линии графика на «Моём пути». Под сферами — настоящий ползунок `<input type="range">` 1–5 (жёлтый бегунок 44×44, стрелки клавиатуры, `aria-valuetext` словами). Он синхронизирован со сферами в обе стороны. Ни касание, ни перетаскивание не переводят к следующему вопросу: нужно нажать «Дальше» (на последнем вопросе «Готово»), а «Назад» возвращает к предыдущему вопросу с сохранённым ответом. Сегодняшнюю отметку можно «Изменить». Чипы последних 7 дней открывают отметку за прошлый день («Самочувствие за пн, 19 октября»), уже заполненную, если отметка была; она сохраняется полднем того дня (`store.addEvent(..., { at })`: только `checkin`, не в будущем, не старше 7 дней). Новая запись не стирает старую. Везде (графики, плитки, сводка и лента врача) берётся последняя записанная отметка дня (`KK.util.latestPerDay`); в ленте врача у неё пометка «пациент изменил отметку» / «внесено <дата>». Ошибочную сегодняшнюю отметку приёма можно снять повторным касанием с подтверждением «Отменить отметку?» (`store.removeEvent` — только сегодняшние `dose`). Линейки, которые только показывают данные, остаются без «ручки».
3. **Опросники** — PHQ-9, GAD-7 пошагово, прогресс-точки, можно прервать и продолжить; итог словами + «результат отправлен врачу». При ответе >0 на п.9 PHQ-9 — сразу мягкий экран поддержки с контактами помощи.
4. **Мой путь** — сверху плитки данных: «Дни с приёмом» N из 14 с кольцом (без подтверждённого плана — «Лечение: Врач обсуждает план»), «Настроение» и «Сон» — ряд точек + слово тренда (ровнее / как обычно / труднее|хуже, `patientApp.trendWord`, тот же расчёт, что в `checkinSummary`), «Практика дня» (ссылка, минуты), «Отметок самочувствия» N дн. Ниже — график динамики без цифровых порогов тяжести, календарь приёмов по дням (оставлен: показывает, какие именно дни), опросники словами. Ни баллов PHQ/GAD, ни слов тяжести, ни красного (тест `patient path tiles`).
5. **Самочувствие на терапии** — НЯ из инструкции (головная боль, головокружение, сонливость, парестезии, астения; реже — бессонница, усиление тревоги, тошнота и др.) с выбором «нет/немного/сильно» + свободный текст.
6. **Связь с врачом** — сообщения, «вопрос врачу», следующий визит.
7. **Материалы** — психообразование (тревога, депрессия, как работает лечение), о препарате простым языком (алкоголь исключить, вождение при сонливости), практики (дыхание, заземление 5-4-3-2-1, поведенческая активация, гигиена сна).
8. **«Мне сейчас очень плохо»** — фиксированная кнопка на всех экранах: телефоны (112; телефон доверия 8-800-2000-122 для детей/подростков; бесплатная психологическая помощь МЧС 8-495-989-50-50 — актуальность проверить при реализации), упражнение заземления, «врач уведомлён».
9. **Профиль** — данные, напоминания, частота опросов, тема.

## 6. Экраны врача

Режим подсказок по специальности: для «не-психиатра» — развёрнутые интерпретации шкал, явные блоки маршрутизации; для «психиатра» — компактно.

1. **Сегодня / пациенты** — очередь по срочности: критические алерты → «обязательно к психиатру» → важные → пропуски приёма → остальные; фильтры, поиск.
2. **Карточка пациента** — шапка (диагноз МКБ-10, риски, противопоказания, аллергии), под кнопками действий — «Сводка» плитками данных (`doctorApp.summaryTiles`): PHQ-9 (широкая, кольцо value/27, интерпретация), GAD-7 (полоса с делениями 0–4/5–9/10–14/15–21), приверженность % за 14 дн., колебания настроения (σ по последним 14 отметкам, шкала 1–5, + ряд точек), НЯ за 14 дн. (чаще всего), дней на терапии; неполная/отсутствующая шкала — «—» и «нет данных»; графики PHQ-9/GAD-7 (дублирующие точечные числа над графиком убраны), лента событий, НЯ, приверженность (% доз), плашки маршрутизации с объяснением «почему» и источником, кнопки действий («Подтвердить направление», «Изменить план» — всё через подтверждение).
3. **Оценка на приёме** — шкалы с автоподсчётом, интерпретацией и ссылкой на валидацию.
4. **Терапия** — справка по Авиандру из инструкции ГРЛС, автоматическая проверка противопоказаний и взаимодействий с текущими назначениями; предложение → «Подтвердить» врачом. Применение вне инструкции — только явным действием врача с отметкой.
5. **Маршрутизация** — список сработавших правил «обязательно/желательно», текст обоснования, шаблон направления.
6. **Алерты** — журнал: время поступления данных, время доставки, время реакции, действие.
7. **Импорт истории болезни** — вставка текста, подсветка извлечённых сущностей (диагнозы, препараты, СКФ, Child-Pugh, беременность, эпилепсия), ручная правка.
8. **Сообщения**, 9. **Материалы** (КР Минздрава, инструкции, шкалы), 10. **Профиль** (специальность, уведомления).

## 7. Алертинг и маршрутизация

| Уровень | Триггеры (демо-набор) | Действия системы |
|---|---|---|
| Критический | PHQ-9 п.9 > 0; C-SSRS скрининг положительный; кнопка SOS; серьёзное НЯ | Модальное окно + звук у врача, наверх очереди, пациенту — экран помощи, запись в журнал; маршрутизация «обязательно» |
| Важный | PHQ-9 ≥ 20; рост PHQ-9/GAD-7 ≥ 5 баллов; ≥3 дней пропуска приёма; новое противопоказание/взаимодействие | Плашка в карточке, подъём в очереди, без модалки |
| Инфо | PHQ-9 15–19; GAD-7 ≥ 15 без улучшения за 4 нед.; лёгкие НЯ | Пассивно в карточке |

**«Обязательно к психиатру»:** суицидальный риск; PHQ-9 ≥ 20; психотические симптомы/подозрение на биполярное расстройство (из истории болезни); отсутствие ответа после адекватного курса. **«Желательно»:** PHQ-9 15–19, коморбидность, повторные эпизоды. Конкретные пороги сверить с КР Минздрава «Генерализованное тревожное расстройство» и «Депрессивный эпизод, рекуррентное депрессивное расстройство» на этапе плана; каждое правило хранит ссылку на источник.

**Принятые отклонения (по итогам ревью ядра):**
- Лекарственное взаимодействие остаётся информационным (пассивно в карточке), а не «важным»: оно известно до назначения и видно в проверке препарата; отдельный алерт дублировал бы его и усиливал «усталость от тревог».
- SOS и выраженное НЯ — критические, но без автоматической маршрутизации к психиатру: причина может быть соматической или ситуативной, решение о направлении принимает врач.
- Правило, которое не удалось вычислить из-за ошибки данных, не молчит: оно показывается как «Правило не вычислено» (уровень не ниже «важного»), чтобы сбой не выглядел как отсутствие риска.

## 8. Шкалы

- **PHQ-9, GAD-7** — свободное использование (Pfizer), валидированные русскоязычные версии; источники валидации указать на странице «Материалы».
- **C-SSRS (скрининговая версия)** — бесплатна для клинического использования, есть русская версия.
- **HADS** — требует лицензии GL Assessment → в демо не используется (опционально, с пометкой).
- **Приверженность** — доля принятых доз по журналу (PDC) + один вопрос самоотчёта; MMAS-8 не используется (лицензия).

## 9. Препарат «Авиандр» (маритупирдин, таблетки 20 мг)

Источник — инструкция (ЛП-№(002445)-(РГ-RU) от 31.05.2023; Vidal, ред. 23.07.2026; сверить с ГРЛС при реализации).
- Показания: ГТР (F41.1); тревожные состояния после COVID-19 при стрессовой реакции и расстройстве адаптации лёгкой и средней степени.
- Режим: 20 мг 2 раза в сутки; длительность — врач.
- Противопоказания: гиперчувствительность; эпилепсия, органические заболевания мозга; ИМАО одновременно и 2 недели после; СКФ < 60 мл/мин; печёночная недостаточность Child-Pugh A–C; < 18 лет; беременность и лактация.
- С осторожностью: сердечно-сосудистые заболевания, пожилой возраст; серотонинергические препараты (СИОЗС, триптаны, трамадол, литий, фентанил, зверобой) — риск серотонинового синдрома; ингибиторы CYP2D6; усиление седации с бензодиазепинами, нейролептиками, барбитуратами, H1-блокаторами; алкоголь исключить.
- Препарат под дополнительным мониторингом безопасности → акцент на сбор НЯ.

## 10. Клинические сценарии

1. **ГТР у терапевта** — показан, проверки пройдены, назначение по подтверждению.
2. **На СИОЗС (сертралин)** — предупреждение о серотониновом синдроме и CYP2D6.
3. **ХБП, СКФ 52** — противопоказание, подсказка о направлении к психиатру для выбора терапии.
4. **Тревожно-депрессивное, PHQ-9 = 21, п.9 > 0** — «обязательно к психиатру», критический алерт.
5. **Тревога после COVID-19, расстройство адаптации** — показан, мониторинг динамики.

## 11. Проверка

- Ручной прогон каждого сценария в браузере (обе роли в двух вкладках), скриншоты.
- Юнит-проверки `scales.js` и `rules.js` (node, без зависимостей): подсчёт, пороги, срабатывание правил по сценариям.
- Мобильная ширина 375px, светлая/тёмная тема, контраст WCAG AA.
- Метрика эргономики: число действий на типовой сценарий (чек-ин ≤3 тапа; подтверждение направления ≤2 клика из очереди).

## 12. Открытые вопросы

- Реальные референсы пользователя по оформлению (опционально) — могут скорректировать палитру/шрифты.
- Актуальность номеров экстренной помощи — сверить при реализации.
- Точные пороги маршрутизации — сверить с действующими КР.

## 13. Роль: клинический психолог (2026-10-20, `feat/psychologist`)

Третий кабинет — первичный приём клинического психолога: пациент проходит батарею тестов у себя в телефоне, психолог видит сводку и предложение маршрута, подтверждает или меняет его, передаёт лечащему врачу.

**Правовые рамки.** Психолог не устанавливает диагноз психического расстройства: это делает врач-психиатр (Закон РФ от 02.07.1992 № 3185-1 «О психиатрической помощи и гарантиях прав граждан при её оказании»). В интерфейсе — «предварительная оценка», «направление на консультацию». Пациент не видит ни баллов, ни уровней, ни интерпретаций: только «Ответы переданы психологу».

### 13.1 Батарея и порядок (≈ 20 минут)

1. **Короткая анкета** — жалобы в 1–2 фразах, что привело сейчас, обращения к психиатру, принимаемые препараты (если да — какие), «видели/слышали то, чего не видят другие», периоды очень приподнятого настроения с малой потребностью во сне.
2. **Скрининг безопасности — C-SSRS (скрининг, самоотчёт).** Стоит вторым намеренно (safety-first): при риске пациент видит экран помощи до длинных опросников, а у психолога и врача поднимается критический сигнал (то же правило `cssrs_risk`). Вопросы 3–5 — только после «да» на вопрос 2. Батарею можно продолжить позже с TIPI-RU. Формулировки самоотчёта — пересказ скрининговой версии на «вы»; **сверить с официальной русской C-SSRS Screen Self-Report** (cssrs.columbia.edu).
3. **TIPI-RU** — профиль личности, 10 пунктов, 1–7; обратные пункты 2, 4, 6, 8, 10 (значение 8 − x); черта = среднее двух пунктов. В маршрутизации не используется.
4. **DASS-21** — 3 подшкалы × 7 пунктов (0–3), балл подшкалы = сумма × 2.
5. **ЦТО (по желанию)** — для 8 понятий («Я», «Я в будущем», «Мама», «Папа», «Близкий человек», «Работа/учёба», «Моя болезнь/проблема», «Врач/лечение») пациент выбирает все 8 цветов Люшера по порядку «насколько подходит», затем раскладывает цвета по приятности. Хранятся сырые раскладки.

Мастер пациента (`patient/intake.html`): один вопрос на экран, прогресс, «Назад», «Сделать перерыв» (черновик в `sessionStorage`; отправленные части повторно не проходятся), плитка «Первичная беседа с психологом · около 20 минут» на «Сегодня», пока приём назначен и не завершён. Цветовые карточки ≥ 44px, с подписью названия и `aria-label`, `aria-pressed`, номер порядка, «Отменить». Красного в интерфейсе пациента нет; оранжево-красная карточка ЦТО — стимульный цвет методики, не семантика.

### 13.3 Предложение маршрута (правила команды, до экспертной проверки)

Каждая причина хранит текст, источник, `teamRule: true` и пометку «правило команды, до экспертной проверки». Применяется самый высокий сработавший уровень (`assets/battery.js` → `KK.battery.routeIntake`).

| Уровень | Условия |
|---|---|
| Психиатр — обязательно | C-SSRS умеренный/высокий (также критический алерт); DASS Депрессия ≥ 21 или Тревога ≥ 15; анкета: психотические или (гипо)маниакальные признаки |
| Психотерапия — желательно | любая подшкала DASS в умеренной полосе (Д 14–20, Т 10–14, С 19–25) или Стресс ≥ 26 |
| Консультирование | лёгкие значения (Д 10–13, Т 8–9, С 15–18) |
| Наблюдение | все подшкалы в норме |

Полосы DASS-21 (Lovibond, 1995): Депрессия 0–9 / 10–13 / 14–20 / 21–27 / 28+; Тревога 0–7 / 8–9 / 10–14 / 15–19 / 20+; Стресс 0–14 / 15–18 / 19–25 / 26–33 / 34+. Нет данных → «нет данных», уровень не предлагается, если ничего не сработало; NaN не бывает.

**Расхождения — вопросы для беседы, а не выводы:** высокие DASS при «всё в порядке» в анкете; DASS (депрессия, тревога) в норме при положительных ответах C-SSRS; повышенный стресс при норме депрессии и тревоги.

**Решение психолога.** «Подтвердить маршрут» или «Изменить» (уровень + обязательная причина, если отличается от предложения) → `store.confirmIntake`, событие `intake_decision`, аудит с автором `psy1`. «Передать лечащему врачу» → `store.handoffIntake`: входящие врача + компактная карточка «Первичный приём психолога» в карточке пациента у врача (дата, маршрут, полосы DASS, сообщение, ссылка «Подробнее»).

### 13.4 ЦТО без автоматической интерпретации

Психолог видит полосы цветов по каждому понятию и нейтральный список совпадений раскладок (ранговая корреляция Спирмена между понятиями и с порядком предпочтения: «“Я” и “Мама”: раскладки близки (ρ = 0,98)»), с подписью «совпадения раскладок — материал для беседы, не интерпретация». Никаких психологических заключений из ЦТО система не делает; в маршрутизации ЦТО не участвует.

Данные v1 мигрируют на месте.

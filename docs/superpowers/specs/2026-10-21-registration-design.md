# Регистрация и вход для всех ролей — дизайн

Дата: 2026-10-21. Статус: дизайн утверждён пользователем.
Запрос: «сделай страницы регистрации для каждого пользователя и как будет это выглядеть на сайте».

## 1. Решения пользователя

- **Пациент** регистрируется только по приглашению врача (код `KMP-xxxx` или ссылка), подтверждает телефон кодом из SMS, даёт согласия.
- **Врач и психолог** регистрируются по приглашению клиники: администратор приглашает по почте, специалист задаёт профиль, пароль и второй фактор. Проверку по ФРМР делает клиника; в системе — отметка администратора.
- **Объём:** рабочие шаги для всех ролей на мок-данных, общая страница входа на сайте, восстановление доступа, вид на телефоне и компьютере.

## 2. Рамки и честность демо

- SMS и письма не отправляются: код или ссылка показываются на экране в плашке «Демо: …».
- Пароли нигде не сохраняются и не проверяются при входе; при регистрации и смене проверяется только надёжность.
- Сессия хранится в `sessionStorage` вкладки (`kk:session`).
- Лаунчер с дверями «Врач / Пациент / Психолог» остаётся; кабинеты не закрываются входом. Если сессия есть, кабинет показывает «Вы вошли как …» и «Выйти»; режим подсказок врача берётся из специальности вошедшего.
- В демо все врачи видят одних и тех же демо-пациентов.

## 3. Страницы

| Страница | Кто | Что делает |
|---|---|---|
| `auth/login.html` | все | Переключатель «Я пациент / Я специалист». Пациент: телефон → код из SMS → дневник. Специалист: почта + пароль → код второго фактора → кабинет своей роли. Ссылки «Регистрация по приглашению» и «Не могу войти» |
| `patient/onboarding.html` (доработка) | пациент | Шаги: приветствие → код врача (подставляется из ссылки и `startapp`) → **телефон и код из SMS** (в MAX — кнопка «Поделиться номером» через `requestContact`, иначе ввод вручную) → согласия → дневник |
| `auth/invite.html?token=…` | врач, психолог, администратор | Приглашение (клиника, роль, почта) → ФИО и специальность (врач — из списка; психолог — «клинический психолог») → пароль ≥ 10 символов с подсказкой надёжности и телефон для второго фактора → код второго фактора → обязательство о врачебной тайне и работе с персональными данными → кабинет |
| `auth/recover.html` | все | Пациент: телефон → код → дневник. Специалист: почта → ссылка (в демо — на экране) → код второго фактора → новый пароль → вход |
| `admin/index.html` | администратор клиники | Пригласить сотрудника (почта, роль), список сотрудников и приглашений со статусами «приглашён / активен / заблокирован / истекло / отозвано», «Отправить ещё раз», «Отозвать», «Заблокировать», отметка «Проверено по ФРМР» |

**Вид на сайте.** Страницы входа, приглашения и восстановления — в раскладке «две колонки» на ширине ≥ 900 px: слева панель с названием, одной фразой о сервисе и тремя пунктами о защите данных (данные в РФ, доступ только лечащим специалистам, вход с подтверждением); справа форма. На телефоне — одна колонка, панель сворачивается в заголовок. Онбординг пациента в браузере (`KK.host.platform === 'web'`) получает ту же левую панель; в MAX и Telegram остаётся полноэкранным. Палитра: вкладка пациента и онбординг — спокойная пациентская, вкладка специалиста, приглашение, восстановление специалиста и администратор — палитра персонала.

**Лаунчер** (`index.html`): четвёртая карточка «Вход на сайт» со ссылками на вход и кабинет администратора.

## 4. Данные (стор) и правила

- `db.clinic = { name, staff: [], invites: [], resets: [] }`, демо-набор: администратор Анна Смирнова (`admin@clinic.demo`), врач Елена Иванова (`elena.ivanova@clinic.demo`, существующий `d1`), психолог Мария Белова (`maria.belova@clinic.demo`, `psy1`), все активны.
- Сотрудник: `{ id, email, role: 'doctor'|'psychologist'|'admin', name, specialty, phone, status: 'invited'|'active'|'blocked', frmrChecked, createdAt, activatedAt }`.
- Приглашение: токен 24 символа `[A-Za-z0-9]`, живёт 72 часа, одно использование; «Отправить ещё раз» выдаёт новый токен и новый срок, старый перестаёт работать; отозванное не принимается. Повторное приглашение на почту активного сотрудника — отказ.
- Одноразовый код (SMS / второй фактор): 6 цифр, живёт 5 минут, не больше 5 попыток, после успешной проверки сгорает.
- Ссылка восстановления специалиста: 30 минут, одно использование.
- Телефон пациента нормализуется к `+7XXXXXXXXXX` (принимаются `8…`, `7…`, `+7…`, пробелы, скобки, дефисы); один номер — один пациент.
- Надёжность пароля: не короче 10 символов, не только цифры, не из списка частых, не содержит часть почты до `@`.
- Заблокированный сотрудник не может войти; приглашённый (ещё не активный) — тоже.

## 5. Ошибки (тексты)

- Код не подошёл: «Код не подошёл. Осталось попыток: N». После 5 — «Слишком много попыток. Запросите новый код».
- Код истёк: «Срок действия кода истёк. Запросите новый».
- Приглашение: истекло / уже использовано / отозвано / не найдено — отдельный текст и «Попросите администратора клиники отправить приглашение ещё раз».
- Номер уже занят: «Этот номер уже привязан к дневнику. Войдите по номеру телефона».
- Специалист не найден или заблокирован: «Не получилось войти. Проверьте почту или обратитесь к администратору клиники» (без уточнения, что именно не так).

## 6. API-контракт

Дополнить `docs/api/openapi.yaml`: `POST /v1/auth/otp` (запросить код), `POST /v1/auth/otp:verify`, `POST /v1/auth/login` (почта + пароль → требуется второй фактор), `POST /v1/auth/mfa:verify`, `POST /v1/auth/recover`, `POST /v1/auth/recover:complete`, `POST /v1/staff-invites`, `GET /v1/staff-invites/{token}`, `POST /v1/staff-invites/{token}:accept`, `POST /v1/staff-invites/{token}:resend`, `DELETE /v1/staff-invites/{token}`, `PATCH /v1/staff/{id}` (блокировка, ФРМР). Сервер: пароли — только хэш (Argon2id), ограничение попыток по номеру и адресу, коды и токены — из криптостойкого генератора.

## 7. Проверка

- Тесты: нормализация телефона и почты, надёжность пароля, коды (срок, попытки, одноразовость), приглашения (срок, повтор, отзыв, отказ для активного), восстановление, вход заблокированного, режим врача по специальности из сессии, тексты без лишних обещаний, сборка ссылки-демо включает `auth/` и `admin/`.
- Браузер: все шаги трёх ролей и администратора на 375 и 1280 px, консоль без ошибок, аудит переполнения на 320/375/768.
